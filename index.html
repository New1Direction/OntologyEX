How it works

One scoped request. A traceable handoff.

The existing coding agent interprets the domain. The tools preserve selected sources, capture evidence, bound compilation attempts, and package a candidate.

1. Select + model

Acknowledge the source boundary. Build the four-layer model from the selected code and documentation.

→

2. Cite + compile

Capture exact quotations and hashes. Correct structural errors within at most three tracked submissions.

→

3. Review + hand off

Inspect the report and unresolved questions. Export the relevant context for a fresh agent session.

Checks are not permissions. A successful build does not establish business-rule truth, authenticate supplied inputs, or authorize a production action.

Run the example without an API key.

Python 3.11+ and PyYAML are enough for the local demo. It uses a pre-authored payments model, not a live agent or a real transaction.

from a fresh checkout
git clone https://github.com/New1Direction/OntologyEX.git
cd OntologyEX
python3 -m venv .venv
source .venv/bin/activate
python -m pip install 'PyYAML==6.0.3'
python examples/payments-domain/demo.py

Preserve corrections

When the source changes, review what changed with it.

Freeze a new snapshot, propose corrections, compare candidates, and retest affected tasks. Accepted knowledge is not silently replaced.

Detect source drift

Compare selected current files with their snapshot. Hashes establish byte identity, not source truth.

Compare candidates

Inspect changes to source evidence and contract items. The impact report conservatively identifies tasks to rerun.

Keep approval separate

Semantic review and independent tests remain outside the proposing agent. There is no automatic deployment or promotion.
